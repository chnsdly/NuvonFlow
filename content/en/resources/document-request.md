## Document request scope

Document requests should identify the product family, project name or reference, expected document type, language, revision needs, and deadline. If the document must match a customer register, include the register format or naming rule.

Documents are easiest to coordinate when the product scope is stable. If material, connection, quantity, actuator, or accessory requirements are still changing, the document package should be treated as preliminary.

## Common document types

| Document | Typical purpose |
| --- | --- |
| Datasheet | Confirms basic configuration, size, materials, pressure class, and accessory scope. |
| Dimensional drawing | Supports layout, installation clearance, pipe connection, and approval review. |
| IOM manual | Gives installation, operation, storage, and maintenance guidance. |
| Material or compliance declaration | Supports customer review where declaration documents are requested. |
| Inspection and test record | May be used for quality review, pressure testing, or functional confirmation. |
| Packing and marking information | Helps receiving teams check shipment, labels, spare parts, and documentation. |

## Before requesting final files

Confirm that the product scope, material, connection, quantity, document language, tag numbers, and revision expectations are stable. Final controlled documents should match the confirmed quotation or purchase order scope.

## How Nuvon can help

Nuvon can organize document requests by product family, line item, tag number, or shipment group. If the exact document package is not yet known, send the project register or customer requirements and Nuvon can identify which items are likely available and which require confirmation.
